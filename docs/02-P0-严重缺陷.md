## P0-01 资源纹理释放后再使用（use-after-release）

- **位置**：`Engine/Source/Runtime/RenderCore/Private/BufferManagerImpl.cpp:153-182`（`RegisterResourcesBuffer`）
- **附带问题**：同函数 `:172` 的空指针检查恒为假

### 代码

```cpp
void BufferManagerImpl::RegisterResourcesBuffer(ResourcesBufferContext context)
{
    ID3D11Texture2D* texture2D = nullptr;
    HRESULT hr = context.Resources->QueryInterface(IID_PPV_ARGS(&texture2D));

    if (SUCCEEDED(hr))
    {
        texture2D->Release();          // :160  刚拿到的引用立刻释放
    }
    else { Core::ErrorCapture{}("Failed to convert to texture!"); return; }

    ResourcesTextureBuffer textureBuffer;
    textureBuffer.Texture = texture2D; // :168  把已释放的裸指针交给 ComPtr
    ...
    if (textureBuffer.Texture == nullptr || textureBuffer.Name.c_str() == nullptr || textureBuffer.SRV == nullptr) {
        Core::ErrorCapture{}("Content missing when registering resources!");
        return;
    }
```

`ResourcesTextureBuffer::Texture` 是 `ComPtr<ID3D11Texture2D>`（见 `Internal/BufferManagerImpl.h`）。`ComPtr::operator=(T*)` 的语义是"接管所有权 + `AddRef`"，因此 `:168` 会对着**引用计数已经归零、内存已归还的对象**再做一次 `InternalAddRef`。

### 为什么是 P0 而非"偶尔出错"

- 这条路是**每次注册资源型纹理都会走**的唯一路径。项目里 `BufferManagerLoadTexture.cpp` 加载编辑器图标后立即调用它（`AssetPipeline` → `LoadAsset` → `RegisterResourcesBuffer`），因此**编辑器启动加载图标时就已触发**。
- 后果是"定时炸弹"式：`AddRef` 改写的可能是已归还堆块上的内存，也可能什么都看不见；之后 `GetRTexture2D` / `GetRTextureSRV`（`:308` 起）拿到的指针，被 Image/ImGui 采样时读取已释放资源。Debug 层会报 `Live Object at 0x... deleted`，Release 下表现为图标变黑、画面错乱，或随机 `0xC0000005`。
- 附带 `:172` 的 `textureBuffer.Name.c_str() == nullptr` 永远为假（`std::string::c_str()` 不会返回 `nullptr`），原本意图应是 `Name.empty()`。也就是说**资源缺失检查里真正会命中的那一项没被检查**。

### 修复

```cpp
ComPtr<ID3D11Texture2D> texture2D;
HRESULT hr = context.Resources->QueryInterface(IID_PPV_ARGS(texture2D.GetAddressOf()));
if (FAILED(hr) || texture2D == nullptr) {
    Core::ErrorCapture{}("Failed to convert to texture! hr=" + std::to_string(hr));
    return;
}

ResourcesTextureBuffer textureBuffer;
textureBuffer.Texture = texture2D;   // 由 ComPtr 接管，绝不手动 Release
...
if (textureBuffer.Name.empty() || textureBuffer.SRV == nullptr) { ... return; }
```

修复后建议加一条断言：在 `GetRTexture2D` 返回前用 `D3D11` 调试层的 `ReportLiveDeviceObjects` 跑一遍冒烟测试。

## P0-03 交换链 RTV 更新：忽略所有 HRESULT + 手动释放 ComPtr

- **位置**：`Engine/Source/Runtime/RenderRT/Private/RenderRTImpl.cpp:80-106`（`UpdateRenderTargetView`）

### 代码

```cpp
void RenderRTImpl::UpdateRenderTargetView(int width, int height)
{
    if (width == 0 || height == 0) return;
    if (... g_pd3dDeviceContext == nullptr || ... g_pSwapChain == nullptr) return;

    RenderCore::RenderContext::Get().g_pd3dDeviceContext->OMSetRenderTargets(0, nullptr, nullptr);
    MainRenderTarget.Get()->Release();                 // :88  手动释放 ComPtr 持有的对象

    RenderCore::RenderContext::Get().g_pd3dDeviceContext->ClearState();
    RenderCore::RenderContext::Get().g_pSwapChain->ResizeBuffers(0, width, height, DXGI_FORMAT_UNKNOWN, 0); // :93 未检查

    ID3D11Texture2D* pBackBuffer = nullptr;
    RenderCore::RenderContext::Get().g_pSwapChain->GetBuffer(0, IID_PPV_ARGS(&pBackBuffer));               // :97 未检查
    RenderCore::RenderContext::Get().g_pd3dDevice->CreateRenderTargetView(pBackBuffer, nullptr, MainRenderTarget.GetAddressOf()); // :98 未检查
    pBackBuffer->Release();                            // :99  可能为空指针
    ...
}
```

### 问题分解

| 行 | 问题 | 后果 |
| --- | --- | --- |
| `:88` | `MainRenderTarget` 是 `ComPtr`，却对其内部指针手动 `Release()` | 对象已释放但 `ComPtr` 仍指向它；若后续 `:98` 失败，`ComPtr` 不写新值 → **析构时二次 `Release`（double free）** |
| `:93` | `ResizeBuffers` 返回值丢弃 | 只要画面还有任何未释放的 back buffer 引用（RTV、SRV、`GetBuffer` 拿到的纹理就是），`ResizeBuffers` 必失败，但代码继续往下走 |
| `:97` | `GetBuffer` 返回值丢弃 | 上述失败时 `pBackBuffer` 保持 `nullptr` |
| `:99` | `pBackBuffer->Release()` 无判空 | **空指针调用虚函数 → 必然崩溃**（`0xC0000005`，调用点就是这里） |
| `:98` `:105` | `CreateRenderTargetView` / `RSSetViewports` 未检查 | RTV 为空也会继续用，下一帧 `OMSetRenderTargets` 传 `nullptr`，`ClearRenderTargetView(nullptr)` 直接崩 |

### 触发条件（很常见）

- 拖动窗口改变大小 → 每次 `WM_SIZE` 都会走这里（`WindowHandler.cpp:36`）。
- `ResizeBuffers` 失败的经典原因：`:99` 之前 `pBackBuffer` 的引用还没 `Release` 就进入下一次 `WM_SIZE`（窗口快速拖动时 `WM_SIZE` 会连发多次），或者此前有人通过 `GetTexture2D("BackBuffer")` 之类的注册表拿走了引用。一旦失败，`pBackBuffer == nullptr`，`:99` 立刻崩溃。
- 另一种：设备丢失（`DXGI_ERROR_DEVICE_REMOVED`，切显卡/远程桌面/驱动更新）→ 同样走到 `:99`。

### 修复

```cpp
void RenderRTImpl::UpdateRenderTargetView(int width, int height)
{
    if (width <= 0 || height <= 0) return;
    auto& ctx = RenderCore::RenderContext::Get();
    if (!ctx.g_pd3dDeviceContext || !ctx.g_pSwapChain || !ctx.g_pd3dDevice) return;

    // 1. 彻底解绑（RTV/DSV + 清空管线状态），否则 ResizeBuffers 必失败
    ctx.g_pd3dDeviceContext->OMSetRenderTargets(0, nullptr, nullptr);
    ctx.g_pd3dDeviceContext->ClearState();
    ctx.g_pd3dDeviceContext->Flush();

    // 2. 交换链内所有未释放的引用都要先归零（含注册表里指向 back buffer 的纹理）
    MainRenderTarget.Reset();          // ComPtr 自己管引用，绝不手动 Release

    HRESULT hr = ctx.g_pSwapChain->ResizeBuffers(0, width, height, DXGI_FORMAT_UNKNOWN, 0);
    if (FAILED(hr)) { LOG_ERROR("ResizeBuffers failed: ", hr); return; }

    ComPtr<ID3D11Texture2D> backBuffer;
    hr = ctx.g_pSwapChain->GetBuffer(0, IID_PPV_ARGS(backBuffer.GetAddressOf()));
    if (FAILED(hr)) { LOG_ERROR("GetBuffer failed: ", hr); return; }

    hr = ctx.g_pd3dDevice->CreateRenderTargetView(backBuffer.Get(), nullptr, MainRenderTarget.GetAddressOf());
    if (FAILED(hr)) { LOG_ERROR("CreateRenderTargetView failed: ", hr); return; }

    D3D11_VIEWPORT viewport{};
    viewport.Width = static_cast<float>(width);
    viewport.Height = static_cast<float>(height);
    viewport.MaxDepth = 1.0f;
    ctx.g_pd3dDeviceContext->RSSetViewports(1, &viewport);
}
```

另外建议：

- 把"重建 RTV"和"`WM_SIZE` 消息"解耦：`WM_SIZE` 只记录目标尺寸并在消息里 return，真正的重建放到帧循环开头，并且**加一帧延迟/防抖**，避免拖动窗口时每像素重建一次（配合 P2-18 的 `WM_ENTERSIZEMOVE` 定时器一起看）。
- 加设备丢失处理（`Present` 返回 `DXGI_ERROR_DEVICE_REMOVED` 时重建整个设备），否则在远程桌面/驱动更新场景下，即使修好本函数也只能崩在别处。
